🎯 Boundary Value Analysis (BVA) Mathematical Types & Examples

BVA tests the extreme boundaries and immediate neighbors of equivalence classes where defect probabilities peak.

💡 Why do boundaries fail? Developers frequently make "off-by-one" errors (e.g. typing < instead of ≤, starting loops at 0 vs 1, or fencepost errors). Mathematical boundaries represent phase shifts where behavior changes abruptly.

Mathematical Definition of Interval Boundaries

Given interval [min, max] with measurement resolution ε (integers: ε = 1, currency/decimals: ε = 0.01):

BVA TypeFormula Test SetValues CountDescription
2-Value BVA (ISTQB CTFL standard) {min - ε, min, max, max + ε} 4 values per 2-sided interval (2 per boundary) Tests the boundary value itself and its immediately adjacent outside value.
3-Value BVA (Safety-critical) {min - ε, min, min + ε, max - ε, max, max + ε} 6 values per 2-sided interval (3 per boundary) Tests immediately below, exactly on, and immediately above each boundary.
One-sided Boundary (x ≥ min) {min - ε (invalid), min (valid)} 2 values For unbounded limits like minimum driving age ≥ 18.

BVA Coverage Formula

BVA Coverage =
Identified Boundary Values Exercised
Total Identified Boundary Values
× 100%

🚗 Everyday Real-Life Example: Highway Speed Limits [50, 120] km/h

Everyday Logic

A motorway enforcement system states: "Vehicles must drive between 50 km/h and 120 km/h inclusive. Driving below 50 impedes traffic; driving above 120 is speeding."

1
Identify the Interval & Step Resolution
• min = 50 km/h, max = 120 km/h
• Speedometers measure in whole integers: step resolution ε = 1 km/h.
2
2-Value BVA (ISTQB Standard)
• Lower Boundary (50): 49 km/h (Ticket: Too slow) and 50 km/h (Valid minimum)
• Upper Boundary (120): 120 km/h (Valid maximum) and 121 km/h (Ticket: Speeding)
→ Complete Test Set: {49, 50, 120, 121} (4 tests achieve 100% 2-value BVA coverage).
3
3-Value BVA (Safety-Critical Systems)
• Around Min (50): 49 (invalid), 50 (valid), 51 (valid)
• Around Max (120): 119 (valid), 120 (valid), 121 (invalid)
→ Complete Test Set: {49, 50, 51, 119, 120, 121} (6 tests).
4
Decimal Precision Step (Banking Wire Transfer)
• Free wire transfers between €1.00 and €5,000.00 inclusive (ε = €0.01):
• Test Values: €0.99, €1.00, €5,000.00, €5,000.01.
🎯
Key Takeaway: 2-Value BVA tests exactly 2 values per boundary: the boundary value itself and its immediately adjacent outside value.

📊 Equivalence Partitioning (EP) Calculation Cheats & Examples

Divides inputs into equivalence groups where all values are expected to produce the same outcome. Testing one value from each group tests that entire partition.

💡 Why does EP save time? If an algorithm calculates sales tax correctly for an order of $50, testing $51, $52, and $53 is redundant. EP ensures you test every distinct behavior exactly once without wasting execution time.

Partition Categories

  • Continuous Range (e.g. Allowed Age 18 to 65):
    • Valid Partition: Values inside the range (18 to 65) → 1 valid partition
    • Invalid Lower Partition: Values too low (less than 18) → 1 invalid partition
    • Invalid Upper Partition: Values too high (greater than 65) → 1 invalid partition
    • Rule: Continuous ranges always produce 1 Valid and 2 Invalid partitions (3 total).
  • Choice Lists / Discrete Options (e.g. Payment: Visa, PayPal, Cash):
    • Valid Partitions: Each recognized option is 1 valid partition (3 valid partitions)
    • Invalid Partition: Any unrecognized choice (e.g. Bitcoin) → 1 invalid partition
    • Rule: A list of k choices produces k Valid partitions and 1 Invalid partition (k + 1 total).

Minimum Test Cases Formulas (The Multi-Variable Rules)

Min Valid Tests = Largest Number of Valid Partitions in Any Single Field
Min Total Tests = Min Valid Tests + All Invalid Partitions Added Together
⚠️ The Golden ISTQB Rule (Defect Masking): Valid partitions from multiple inputs CAN be combined in a single test case. Invalid partitions must NEVER be combined in the same test case because one defect could mask another!

🎓 Official ISTQB Exam Question Walkthrough: Multi-Field E-Commerce Checkout

Sample Exam A — Q17 & Sample Exam B — Q60
Official Scenario:

"An e-commerce form has 3 input fields: User Type (Registered / Guest), Discount Code (Yes / No), and Cart Value (Above threshold / Below threshold). How many test cases are required for minimum valid EP coverage vs minimum total tests?"

1
Valid Tests Combination (Max Rule)
Field 1 has 2 valid options, Field 2 has 2 valid options, Field 3 has 2 valid options. Because valid inputs can be tested simultaneously:
Min Valid Tests = Max(2, 2, 2) = 2 tests (e.g. TC1: [Registered, Yes, Above], TC2: [Guest, No, Below]).
2
Invalid Tests Isolation (Defect Masking Rule)
If each field has 1 invalid partition (e.g. invalid user, invalid coupon, negative cart):
Min Total Tests = 2 (Valid) + 1 + 1 + 1 (Invalids) = 5 tests.
Never test two invalid inputs in the same test case!
⚠️
Defect Masking Rule: Valid inputs can be combined in shared tests. Invalid inputs must each be tested alone with valid values for all other fields.

Exhaustive Combinatorial Tests (Cartesian Product)

Total Combinations = (Total Partitions of Field 1) × (Total Partitions of Field 2) × …

For 3 fields each having 2 valid + 1 invalid = 3 partitions:

Total Combinations = 3 × 3 × 3 = 27 test cases

📋 Decision Table Testing Calculation Cheats & Examples

Ideal for complex business logic where system outcomes depend on combinations of several conditions.

💡 What is a Decision Table? It documents combinations of inputs (Condition Stubs) and their expected outputs (Action Stubs). Each column represents one distinct business rule.

Maximum Rules Formulas

Total Rules (Binary True/False) = 2C (C = Number of True/False Conditions)
Total Rules (Multi-Option) = (Options for Condition 1) × (Options for Condition 2) × …

The Power of 2: Each True/False condition doubles the number of rules: 1 condition = 2 rules, 2 conditions = 4 rules, 3 conditions = 8 rules, 4 conditions = 16 rules, 5 conditions = 32 rules.

🍕 Everyday Real-Life Example: Pizza Delivery & Free Shipping Rules

Everyday Logic

A pizzeria offers free delivery based on 3 binary conditions (C = 3 → 2³ = 8 rules):

  • C1: Order Value ≥ $30 (True / False)
  • C2: Customer is VIP Member (True / False)
  • C3: Delivery Distance ≤ 5 miles (True / False)
Condition / ActionR1R2R3R4R5R6R7R8
C1: Order ≥ $30?TTTTFFFF
C2: VIP Member?TTFFTTFF
C3: Distance ≤ 5 mi?TFTFTFTF
Action Result Free Delivery Deny (>5 mi) Free Delivery Deny (>5 mi) Free Delivery Deny (>5 mi) $5 Surcharge Deny (>5 mi)
💡
Collapsing Rules with Don't Care (-)
Whenever Distance ≤ 5 mi is FALSE (Rules 2, 4, 6, 8), the action is ALWAYS "Deny Delivery"!
Instead of 4 separate rules, we write 1 collapsed rule: C1 = -, C2 = -, C3 = F → Deny Delivery.
Here k = 2 dashes, so it covers 2² = 4 rules!

Rule Reduction & Don't Care (-) Rules

A dash (-) means "this condition does not affect the outcome". Each dash doubles the number of underlying rules covered by that single rule:

Rules Covered by 1 Collapsed Rule = 2k (k = Number of dashes in that rule)
Completeness Check : Sum of all covered rules must equal 2C
  • If sum < 2C: Table is incomplete (certain input combinations were forgotten).
  • If sum > 2C: Table is inconsistent/contradictory (rules overlap and give conflicting actions).
  • If sum = 2C: Table is 100% complete and consistent.

🔬 White-Box Coverage & Cyclomatic Complexity Examples

White-box testing derives test cases from the internal structure, source code, and control flow of the test object.

Coverage Formulas

Statement Coverage =
Executable Statements Executed
Total Executable Statements
× 100%
Branch Coverage =
Decision Outcomes Exercised
Total Decision Outcomes (Branches)
× 100%

For D binary decision constructs (e.g. if, while):

Total Decision Branches = 2 × D (Every decision has exactly 2 branches: True and False)

⚠️ The Classic "Single If" Trap: Why 100% Statement Coverage is NOT Enough!

Core ISTQB Concept

Consider the following simple speed camera function:

function processSpeed(speed) { if (speed > 100) { // Decision D1 (True or False) triggerSpeedCamera(); // Statement S1 (Executable) } return speed; // Statement S2 (Executable) }
1
Execute Test Case 1 (speed = 120)
• Path: speed > 100 is TRUE → triggerSpeedCamera() → return speed.
• Both S1 and S2 ran! Statement Coverage = 2 / 2 = 100%! 🎉 (Looks green in coverage reports).
2
THE FATAL FLAW (Untested False Branch)
• What happens when speed ≤ 100? The FALSE branch was NEVER tested!
• If there were a bug where the camera flashed anyway, you would never catch it!
• Branch Coverage: Only 1 branch out of 2 was exercised = 50% Branch Coverage.
⚖️
The Subsumption Rule: 100% Branch Coverage ALWAYS guarantees 100% Statement Coverage. 100% Statement Coverage DOES NOT guarantee 100% Branch Coverage.

McCabe's Cyclomatic Complexity V(G)

Calculates the number of linearly independent paths through the code and the minimum test cases required for 100% branch coverage:

Complexity V(G) = Binary Decision Predicates (D) + 1
Complexity V(G) [Graph] = Edges (E) - Nodes (N) + 2P (P = 1 for a single program)

💡 Intuitive Cyclomatic Complexity Walkthrough

Everyday Logic

Suppose a function processes online store discounts:

function calculateDiscount(user) { if (user.isVIP) { applyVIPDiscount(); } // Decision 1 if (user.cartTotal > 100) { applyBulkBonus(); } // Decision 2 if (user.hasCoupon) { applyCoupon(); } // Decision 3 }
1
Count Binary Decision Constructs
Count each if statement: D = 3 decisions.
2
Calculate Complexity V(G)
V(G) = D + 1 = 3 + 1 = 4.
✅ Practical Meaning for Testers:
You need a minimum of 4 test cases to achieve 100% branch coverage of this function!

🎓 Official ISTQB Exam Question Walkthrough: Iteration Effort Extrapolation

Sample Exam C — Q111
Official Exam Stem:

"At the beginning of each iteration, the team uses the formula E(n) = (3 * A(n-1) + A(n-2)) / 4 where A(n) is actual work done. Given actual effort A(4) = 6 person-days and A(3) = 8 person-days, what is estimated work for iteration #5?"

1
Substitute Given Actuals
A(n-1) = A(4) = 6 and A(n-2) = A(3) = 8.
2
Evaluate the Extrapolation Formula
E(5) = (3 × 6 + 8) / 4 = (18 + 8) / 4 = 26 / 4 = 6.5 person-days.
✅ Correct Answer / Solution:
The estimated effort for iteration #5 is exactly 6.5 person-days.
